Sithan Kanna FineWeb shard viewer

Look at the Parameter Golf data

Parameter Golf ships FineWeb as token shards, not text. Each shard is a long stream of uint16 token ids with web pages laid end to end, and every page starts with a BOS token. This page fetches only the bytes it needs from Hugging Face, splits the stream at each BOS and decodes it, so you can step through the documents one at a time. Every step shows the Python that does the same thing (peek_fineweb.py, standard library only).

How the text gets here

Each step runs in your browser. Expand a step to see the Python equivalent, pulled from peek_fineweb.py.

Read manifest.json–

The manifest lists each tokenizer variant (sp1024, sp8192, CaseOps…), where its SentencePiece model is, and how many val and train shards it has. The first num_val_docs documents of the shuffled document list make up the val split, and the rest are train.


          

          

            Parse the SentencePiece model–
            
A .model file is a protobuf. The only thing needed to decode is the list of pieces and their types: <s> (BOS, id 1) is a control token; <0x0A>-style pieces are raw bytes for characters the vocab doesn't cover; ▁ marks a leading space.

            

          

          

            Read the shard header–
            
1024 bytes: 256 little-endian int32s. [0] is the magic 20240520, [1] the version, [2] the token count. Tokens follow as uint16, so token i lives at byte 1024 + 2i. That fixed layout is what lets us fetch any slice with an HTTP Range request.

            

          

          

            Split the stream at BOS–
            
The exporter writes [BOS] + sp.encode(text) for each document and never writes an EOS, so the only place one document ends is where the next BOS begins. Documents also run straight across shard files: a shard is cut at exactly 100M tokens, wherever that lands.

            

          

          

            Decode tokens to text–
            
Join the pieces, turn byte pieces back into UTF-8, drop control tokens, and turn ▁ into a space. For the CaseOps export there is one more step: the text was lowercased before tokenizing, with operator tokens marking where the capitals were (⟨TITLE⟩ word, ⟨ALLCAPS⟩ word, ⟨CAPNEXT⟩ letter, ⟨ESC⟩ literal). That transform is exactly invertible, so bits per byte is still scored against the original bytes.

The boundary, as the model sees it

          
The end of the previous document, then BOS, then the start of this one. The two pages are usually unrelated because the document list was shuffled before export.

          

        


        

          
Where this document lands in a training sequence

          

            The baseline train_gpt.py reads shards as one continuous stream and cuts it into fixed-length sequences, ignoring document boundaries.
            So a single sequence usually holds the tail of one page, a few whole pages, and the head of another, and attention runs across the joins unless the model masks them (the "BOS fix" and VarLen-attention records on the leaderboard deal with exactly this).
